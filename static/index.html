❓ Flujo de trabajo

MyVoices se usa en cuatro pasos: 1) registrar una voz, 2) crear un preset con sus parámetros, 3) usar el preset para reproducir, guardar o llamar desde la API, 4) conectar a un LLM vía MCP o recibir eventos en sistemas externos con webhooks.

1
Clonar o crear una voz
En la pestaña 🎤 XTTS2 sube un archivo .wav de referencia (10-30 s de habla limpia) para clonar una voz, o en 🤖 Piper descarga una voz neuronal del catálogo (sin GPU, más rápida).
↓
2
Crear un preset con parámetros
En la pestaña Principal, sección Configurar preset de voz, elige una voz y ajusta:
  • Velocidad — más lento o más rápido
  • Tono — más grave o más agudo (semitonos)
  • Idioma — solo aplica a XTTS2
  • Efecto radio — bandpass + clipping para sonido walkie-talkie
Guarda con un nombre — ese nombre es lo que se usa en la API.
↓
3. Usar el preset
3.1
▶ Probar el preset
En el Panel de prueba selecciona el preset, escribe un texto y pulsa Reproducir.
3.2
⬇ Guardar el audio
Tras reproducir, pulsa Descargar audio — guarda exactamente el WAV que acabas de oír (no se vuelve a sintetizar).
3.3
💾 Guardar como frase
Escribe un nombre en Guardar frase y guarda. La frase queda asociada al preset y reproducible por nombre vía API.
3.4
📡 Llamar a la API con frase guardada
POST http://localhost:8000/api/phrases/{nombre}/play
Reproduce la frase guardada con su preset asociado. Útil para SAMMI, OBS, o cualquier sistema que dispare nombres fijos.
3.5
📡 Llamar a la API con voz + texto
POST http://localhost:8000/api/speak
Content-Type: application/json

{
  "voice": "nombre_del_preset",
  "text":  "Hola chat, bienvenidos al stream!"
}
Sintetiza y reproduce texto arbitrario con un preset. Para descargar el WAV directamente en lugar de reproducirlo, usa POST /api/speak/download.
↓
4
🤖 Usar desde un LLM (MCP)
Conecta MyVoices a un modelo (Claude, Cursor, Gemini, ChatGPT…) mediante el Model Context Protocol. El servidor MCP envuelve esta misma API REST como herramientas que el modelo puede invocar:
  • get_status, list_voices, list_presets, list_phrases — lectura
  • speak(voice, text) — sintetiza y reproduce
  • play_phrase(name) — dispara una frase guardada
  • download_last_audio — metadatos del último WAV cacheado
Antes de conectar un cliente: activa el servidor MCP desde la pestaña Principal (tarjeta 🤖 Servidor MCP) — el toggle genera el Bearer token y enciende el endpoint /mcp/. Cuando esté ON, elige tu cliente abajo y copia la configuración:

Selecciona un cliente arriba para ver su configuración auto-rellenada con tu URL y token.

↓
5
⚡ Cola de prioridad y webhooks
Todas las peticiones de síntesis pasan por una cola de prioridad: las llamadas de MCP y API externa se procesan antes que las de la UI, y las frases guardadas tienen la prioridad más baja. Esto garantiza que las peticiones del LLM nunca bloqueen la app.
Los webhooks permiten notificar sistemas externos (OBS, Home Assistant, n8n…) cada vez que termina una síntesis. El evento speak_end incluye la voz usada, el texto, el origen (MCP / API / UI) y la duración en milisegundos. 
POST /api/webhooks
{ "url": "https://tu-servidor/hook", "events": "speak_end" }

// Payload recibido:
{
  "event": "speak_end",
  "voice": "SexyGirl",
  "text": "Hola chat…",
  "caller": "MCP",
  "duration_ms": 1240
}
Gestiona los webhooks desde el panel Webhooks en la pestaña Principal: añadir, eliminar y probar la conexión con un clic.
↓
6
📋 Registro de actividad
El Registro de actividad (panel inferior de la pestaña Principal) muestra cada llamada con su contexto completo:
  • Origen — badge de color: MCP API UI
  • Preset — nombre del preset usado
  • Texto — vista previa (primeros 60 caracteres)
  • ms — duración de la síntesis en milisegundos
Filtra por nivel (INFO / WARNING / ERROR) y por origen para ver solo las llamadas que te interesan. El log se refresca automáticamente cada 5 s cuando el panel está abierto.
